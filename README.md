# Aster 演示站

一个用于演示 **dsh-superagent** 的最小前端项目：单页产品官网，HTML + CSS + 原生 JS，没有任何构建步骤和外部依赖。

用它来观察智能体接到请求后会做什么：改一行文案、调一处间距，改动都能在浏览器里立刻看见。

## 本地预览

直接双击 `index.html`，或者起一个静态服务：

```powershell
cd D:\superagent-demo
python -m http.server 8090
```

然后打开 http://127.0.0.1:8090

## 怎么触发智能体

在仓库的 Issue 或评论里，@ 智能体账号并写下要求：

```
@<智能体账号> 首页那段介绍里的"协做"是错别字，改成"协作"
```

一分钟左右，superagent 面板的概览里会出现一张工单，随后智能体在自己的 Session 里改代码、开分支、提 PR，并回到这条 Issue 里回复。

## 预置的演示任务

仓库里刻意留了几个小问题，正好对应 superagent 默认策略里的两类规则（文案修正、视觉微调）。按顺序试，能看到从"一句话"到"一次提交"的完整链路。

| # | 位置 | 问题 | 对应规则 |
| --- | --- | --- | --- |
| 1 | `index.html` 首屏介绍段 | “帮助团队更高效地**协做**” —— 错别字，应为“协作” | 文案修正 |
| 2 | `index.html` 第三张特性卡片 | “支持按作者和时间范围**筛选举例**” —— 语义不通，应为“筛选” | 文案修正 |
| 3 | `style.css` `.feature-card` | 三张卡片内边距不一致：第一、三张 `24px`，第二张 `20px`，应统一 | 视觉微调 |

这三条都写得足够具体（指明了位置和目标值），符合策略里"显式请求"的要求。如果把要求写模糊，比如"这个页面不好看"，智能体会按 `observe` 模式只记录、不动手——这也是可以演示的一部分。

## 结构

```
index.html    页面结构
style.css     样式（含深色模式变量）
app.js        深色模式切换、回到顶部
```
